# FIDES v1 → v2 Migration Guide

**Target version:** `fides-v2.0.0`

This guide covers all breaking changes and new features when upgrading from
FIDES v1 to v2. Follow the steps sequentially — some steps depend on earlier
ones.

---

## 1. Package Changes

### New packages (install these)

| Package | Purpose |
|---------|---------|
| `@fides/guard` | Pre-execution guard decision engine |
| `@fides/discovery` | Multi-provider agent discovery orchestrator |
| `@fides/runtime` | TEE attestation adapter + kill switch engine |
| `@fides/evidence` | Hash-chained, Merkle-rooted evidence ledger |
| `@fides/registry-service` | Central AgentCard registry |
| `@fides/relay-service` | Message relay for NAT/firewall agents |
| `@fides/agentd` | Local daemon proxying all trust fabric services |

### Renamed packages

| v1 Package | v2 Package | Notes |
|-----------|-----------|-------|
| `@fides/trust` | `@fides/trust-graph` | New scoring formula, capability edges |
| `@fides/did` | *merged into `@fides/sdk`* | DID utilities now in core SDK |

### Unchanged packages

`@fides/sdk`, `@fides/shared`, `@fides/core` — these remain but have additional
exports for v2 types.

## 2. Identity Changes

### Before (v1)

```typescript
// Simple DID string, no metadata
const did = 'did:fides:CVDFLCAjXhVWiPXH9nTCTpCgVzmDVoiPzNJYuccr1dqB'
```

### After (v2)

```typescript
interface Identity {
  did: string
  type: 'agent' | 'publisher' | 'principal' | 'trust-anchor'
  publicKey: Uint8Array
  metadata: Record<string, unknown>   // NEW: extensible metadata
  createdAt: string                    // NEW: ISO 8601 timestamp
}
```

**Migration steps:**
1. Add `type` field to all identity records
2. Populate `metadata` with any existing custom attributes
3. Update DIDs generated by your system to include type declarations
4. Update any code that assumed identity === DID string

## 3. Trust Graph Changes

### Scoring formula

| | v1 | v2 |
|---|----|----|
| Direct trust (depth 1) | ×0.7 | ×1.0 |
| Transitive depth 2 | ×0.3 | ×0.5 |
| Transitive depth 3+ | (not computed) | ×0.25 |
| Final score | capped at 0.7 | capped at 1.0 |

### Capability edges (NEW)

v2 introduces capability-scoped trust edges:

```typescript
interface TrustEdge {
  // ... existing fields
  capabilityId?: string  // NEW: null = general trust, string = scoped
}

// v2 also tracks:
interface CapabilityScore {
  did: string
  capabilityId: string
  score: number              // 0–1
  invocationCount: number    // NEW
  incidentCount: number      // NEW
  lastComputed: string
}
```

**Migration steps:**
1. v1 trust edges without `capabilityId` → imported as general trust (null)
2. Recompute all reputation scores using the v2 formula
3. Populate `invocationCount` and `incidentCount` from audit logs if available
4. API paths changed from `/v1/trust/:did` to `/v1/trust/:did/score`

## 4. New Features to Adopt

### 4.1 AgentCard v2

```typescript
interface AgentCard {
  id: string
  did: string
  name: string
  description: string
  version: string
  capabilities: CapabilityDescriptor[]   // NEW
  protocols: string[]                    // NEW: e.g. ["mcp", "a2a"]
  endpoints: AgentEndpoint[]             // NEW
  security: SecurityProfile              // NEW
  metadata: Record<string, unknown>      // NEW
}
```

**Action:** Register AgentCards via the Registry service (`POST /v1/cards`).

### 4.2 Policy Engine

v2 adds a pre-execution pipeline before policy rules:

1. Kill switch check → immediate deny if engaged
2. Attestation check → deny if invalid/expired
3. Evidence chain → deny if hash chain broken
4. Incident rate → deny if ≥5 incidents in 24h
5. Trust score → factor into decision

**Action:** Define policy bundles with rules, constraints, and default action.
Upload via agentd: `POST /v1/policy/evaluate`.

### 4.3 Evidence Ledger

Hash-chained, Merkle-rooted evidence events with privacy levels:

```typescript
interface EvidenceEvent {
  // ... event data
  privacy: { level: 'public' | 'private' | 'redacted' | 'hash-only' }
  prevHash: string  // hash of previous event
  hash: string      // SHA-256 of this event
}
```

**Action:** Send evidence via agentd: `POST /v1/evidence`. Verify chain integrity:
`GET /v1/evidence/:did`.

### 4.4 Guard Decision Engine

Use `@fides/guard` for unified decision-making:

```typescript
import { evaluateGuard } from '@fides/guard'

const decision = await evaluateGuard({
  agentDid: 'did:fides:agent01',
  capabilityId: 'payment:charge',
  policy: myPolicyBundle,
  context: { amount: '100' },
  trust: { reputationScore: 0.9, ... },
})
// → { decision: 'allow' | 'deny' | 'approve-required' | 'dry-run' }
```

### 4.5 Kill Switch

Emergency shutdown with precedence:

- Global kill overrides all
- Agent kill overrides capability kills for that agent
- Capability kill affects all agents for that capability

**Action:** Engage via agentd:
```
POST /v1/killswitch/engage  { global: true }
POST /v1/killswitch/engage  { did: "did:fides:agent01" }
POST /v1/killswitch/engage  { capabilityId: "payment:charge" }
```

## 6. API Changes

### New endpoints

**Registry (`:7346`):**
| Method | Path | Description |
|--------|------|-------------|
| POST | `/v1/cards` | Register AgentCard |
| GET | `/v1/cards/:did` | Get card |
| DELETE | `/v1/cards/:did` | Delete card |
| POST | `/v1/cards/:did/mode` | Toggle public/private |
| GET | `/v1/search?q=` | Search cards |
| GET | `/v1/stats` | Registry statistics |

**Relay (`:7347`):**
| Method | Path | Description |
|--------|------|-------------|
| POST | `/v1/relay` | Submit message |
| GET | `/v1/relay/:did/messages` | Poll messages |
| GET | `/v1/relay/:id` | Get message by ID |
| DELETE | `/v1/relay/:id` | Delete message |
| GET | `/v1/relay/stats` | Relay statistics |

**Agentd (`:7345`):**
| Method | Path | Description |
|--------|------|-------------|
| GET | `/v1/identities/:did` | Identity resolution (proxy) |
| GET | `/v1/cards/:did` | Agent card lookup (proxy) |
| GET | `/v1/trust/:did/score` | Trust score (proxy) |
| POST | `/v1/policy/evaluate` | Policy evaluation |
| POST | `/v1/evidence` | Submit evidence |
| GET | `/v1/evidence/:did` | Retrieve evidence chain |
| POST | `/v1/attest` | Create attestation |
| GET | `/v1/killswitch/status` | Kill switch status |
| POST | `/v1/killswitch/engage` | Engage kill switch |
| POST | `/v1/killswitch/disengage` | Disengage kill switch |

### Changed response formats

- **Identity responses** now include `type`, `metadata`
- **Trust score** now includes `computedAt` and capability-level breakdowns
- **Agent cards** now include `capabilities`, `endpoints`, `security` objects
- All timestamps are now ISO 8601 strings (previously Unix timestamps in some endpoints)

### API key authentication

v2 services that accept writes (registry, relay, agentd) support API key auth:
- Set `SERVICE_API_KEY` environment variable
- Include `X-API-Key` header on requests
- GET requests skip auth (read-only)

## 7. Database Migration

### Discovery Service

New columns on `agents` table:
```sql
ALTER TABLE agents ADD COLUMN capabilities jsonb DEFAULT '{}';
ALTER TABLE agents ADD COLUMN skills jsonb DEFAULT '[]';
ALTER TABLE agents ADD COLUMN default_input_modes text[] DEFAULT '{}';
ALTER TABLE agents ADD COLUMN default_output_modes text[] DEFAULT '{}';
```

### Trust Graph Service

New tables:
```sql
CREATE TABLE capability_scores (
  did TEXT NOT NULL,
  capability_id TEXT NOT NULL,
  score DOUBLE PRECISION NOT NULL DEFAULT 0,
  invocation_count INTEGER NOT NULL DEFAULT 0,
  incident_count INTEGER NOT NULL DEFAULT 0,
  last_computed TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (did, capability_id)
);

CREATE TABLE capability_invocations (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  did TEXT NOT NULL,
  capability_id TEXT NOT NULL,
  invoked_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE incidents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  did TEXT NOT NULL,
  capability_id TEXT NOT NULL,
  description TEXT NOT NULL,
  severity TEXT NOT NULL DEFAULT 'medium',
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### Registry Service

Uses PostgreSQL for durable hosted registry state in production. Local development can still use file-based persistence at `~/.fides/registry/registry.json`.

### Relay Service

No database — in-memory only.

4. [ ] Update identity type declarations (`agent` | `publisher` | `principal` | `trust-anchor`)
5. [ ] Recompute trust scores using v2 formula
6. [ ] Register AgentCards via registry service
7. [ ] Define policy bundles for capability gating
8. [ ] Set up evidence submission for audit trails
9. [ ] Configure kill switch endpoints for emergency shutdown
10. [ ] Start registry and relay services if needed
11. [ ] Update API clients for new response formats
12. [ ] Run integration tests against all services
13. [ ] Run load tests to validate performance
